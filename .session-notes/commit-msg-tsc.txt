refactor(frontend): close typed-state end-to-end (api + useState + casts)

End the typed `Invoice` contract at the API and `useState` boundaries,
closing the only remaining `as any` / `useState<any>` / `as InvoiceStatus`
loose-typing surfaces in the frontend data flow. Five file touches plus
two recovery fixes from the placeholder-shape gap; single atomic commit
per `#19` cohesive-cleanup directive.

## What changed

### Five file edits

1. `frontend/lib/utils.ts` — type additions only.
   * New `ApiResponse<T>` envelope
     `{ success: boolean; data: T; error?: string; pagination?: {...} }`.
     Mirrors `backend/src/controllers/invoice.controller.ts`.
   * New `PaymentSession`
     `{ invoice: Invoice; paymentUrl: string; qrCode: string; stellarQrCode: string }` —
     shared shape for `createInvoice` and `getPaymentInfo` endpoints.
   * New `InvoiceStats` (per-asset aggregate row, with `string | number`
     for SQL aggregate values that arrive as `string` from node-postgres).
   * New `CreateInvoiceInput` (frontend mirror of backend
     `backend/src/utils/validation.ts`).

2. `frontend/lib/api.ts` — full `invoiceApi` retype.
   * Every method (`create`, `getById`, `getAll`, `getPaymentInfo`,
     `cancel`, `verify`, `getStats`) gets an explicit
     `Promise<ApiResponse<T>>` return signature and an
     `api.post<ApiResponse<T>>(…)` / `api.get<ApiResponse<T>>(…)` generic.
   * `stellarApi` and `healthCheck` deliberately kept `any`-typed (see
     PR #1 "Known followups"); cohesive-cleanup scope is `invoiceApi`
     only.
   * `USE_MOCK_API ? mockInvoiceApi : realInvoiceApi` collapses to a
     single type via the api↔mock boundary cast (see Recovery below).

3. `frontend/app/page.tsx` —
   * `useState<any>` for `createdInvoice` → `useState<PaymentSession | null>`.
   * `handleInvoiceCreated = (result: any) => …` →
     `(result: PaymentSession) => …`.
   * `InvoiceForm` passes `result.data` (unwrapped PaymentSession) to
     `onSuccess`; the parent's typed handler accepts that exactly.

4. `frontend/app/dashboard/page.tsx` —
   * `useState<any[]>` for `invoices` AND `filteredInvoices` →
     `useState<Invoice[]>`.
   * `useState<any>` for `stats` → `useState<InvoiceStats | null>`.
   * `setStats(statsResult.data[0] || {})` → `?? null`; subsequent
     `{stats && (…)}` guards already handle the null case correctly.
   * `downloadInvoiceCSV(paidInvoices as any)` → `downloadInvoiceCSV(paidInvoices)`.
   * `paymentCompleted(inv.status)` callers compile clean because
     `inv.status: InvoiceStatus` is now typed via `Invoice[]`.

5. `frontend/app/pay/[id]/page.tsx` —
   * `useState<any>` for `paymentInfo` → `useState<PaymentSession | null>`.
   * Four cast removals:
     * line 46: `!interactiveStatus(result.data.status as InvoiceStatus)`
       → `!interactiveStatus(result.data.status)`
     * line 47: `setInvoice(result.data as Invoice)` →
       `setInvoice(result.data)`
     * line 49: `paymentCompleted(result.data.status as InvoiceStatus)`
       → `paymentCompleted(result.data.status)`
     * line 67: `setInvoice(invoiceResult.data as Invoice)` →
       `setInvoice(invoiceResult.data)`

### Recovery: api↔mock boundary cast

After the api retyping, tsc surfaced a regression section chain:
`mockInvoices` in `frontend/lib/mock-api.ts` is `any`-inferred with
literal `status: string` widening; the conditional
`USE_MOCK_API ? mockInvoiceApi : { …typed… }` resolved to a union with
`status: string` shapes that defeat `Invoice`'s `status: 'PAID'` literal
discriminator.

Fix at the api/mock seam (single cast, in `api.ts` only — no consumer
effects):

```ts
const realInvoiceApi = {
  create: async (data: CreateInvoiceInput): Promise<ApiResponse<PaymentSession>> => …,
  // … etc
};

export const invoiceApi: typeof realInvoiceApi = USE_MOCK_API
  ? (mockInvoiceApi as typeof realInvoiceApi)
  : realInvoiceApi;
```

The cast is type-only. Runtime compatibility is direct: mock's
`mockInvoices[0]` has PAID fields and `status: 'PAID'`; `mockInvoices[1-3]`
have non-PAID shapes; `create()` produces a non-PAID object; structurally
matches `Invoice`. Re-typing `mock-api.ts` is a separate followup (mock
fields currently inferred to `string`-widened union; outside scope).

### Recovery: two narrow type strictnesses

Two residual `tsc` errors after the api↔mock fix:

1. `frontend/app/dashboard/page.tsx(218,33)` —
   `parseFloat(stats.total_revenue || 0)` where `stats.total_revenue: string | number`.
   Fix: `parseFloat(String(stats.total_revenue ?? 0))`. `String()` is
   lossless for both number and string; runtime semantics unchanged.

2. `frontend/app/pay/[id]/page.tsx(398,21)` —
   `<QRCodeDisplay value={paymentInfo?.stellarQrCode || paymentInfo?.paymentUrl}>`
   produces `string | undefined` under the new `PaymentSession | null`
   typing; `QRCodeDisplay.value: string`. Fix: switch `||` to `??` and
   append `?? ''` so the chain resolves to a literal `string`. Bonus:
   preserves empty-string values that the backend may legitimately emit
   as QR sources (the prior `||` would have skipped them as falsy).
